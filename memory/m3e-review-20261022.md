# M3 Expressive conformance review — 2026-10-22 (read-only, main 67f9ea0)

## Request (confirmed)
"컬러나 UI 구조등 전반적으로 M3Expressive에 맞는지 전부 검토해줘." Review only; nothing changed.

## Evidence used
- Theme code (`theme/Color.kt`, `Theme.kt`, `Shape.kt`, `Type.kt`, `ui/motion/ExpressiveMotion.kt`) and a grep inventory of `ui/` and `lms/`.
- WCAG contrast computed from the hex values in `Color.kt`.
- Material3 1.5.0-beta02 class files (javap) for API availability and type-weight tokens.
- A research agent's reading of m3.material.io on 2026-10-22 (sources inline below).
- Emulator screenshots from 2026-10-22 and a dark-theme capture of the release build on the Galaxy Tab S9.

## Conforms (observed)
- Every UI color is a ColorScheme role: no hex literals, font-weight overrides or corner-radius literals in screens. Both light and dark schemes set every role, including the surfaceContainer levels, surfaceBright/Dim, inverse and Fixed roles (m3.material.io/styles/color/roles).
- Text contrast is at least 6.3:1 in light and 7.2:1 in dark for every on-role pair checked.
- From D-102/D-103:
  - connected button group instead of segmented buttons;
  - filled icon on the active tab, outlined on the others;
  - re-selecting a tab scrolls to the top;
  - fade-through between destinations;
  - tabular figures on countdowns;
  - a full-screen dialog for the course form;
  - one filled button per screen;
  - the snackbar on inverseSurface;
  - hero emphasis limited to the Home briefing and the next-departure capsules.

## Deviations
### Inconsistencies or defects
1. Home next-departure capsules use primaryContainer for the first departure and secondaryContainer for the rest. The Shuttle screen (`shuttleCapsuleColors`) and the D-083 text use primary/onPrimary. In light mode primaryContainer #FFD9E4 and secondaryContainer #FFD9E2 are identical in tone (ratio 1.001), so on Home the first and second departures look the same. The comment in `HomeScreen.kt` says "primary".
2. Dialog confirm actions are mixed. Eight dialogs use filled `Button`s (AppDataCard ×2, MealScreen ×2, CourseOverrideDialog, TermEditorDialog, SettingsScreen ×2). Others use `TextButton`; course delete, for example, is an error-colored TextButton while delete-all and LMS logout are filled error Buttons. The M3 dialog spec uses trailing text buttons.
3. In dark mode the cards (surfaceContainerLow #221A1C on surface #191113, 1.09:1) are barely visible, because elevation shadows do not show on dark backgrounds. Seen on the tablet capture. Light mode is 1.05:1 plus a shadow.
4. D-103's `dimaFadeThrough()` uses `tween`. The M3 motion guidance asks custom animations to use `MaterialTheme.motionScheme` springs.
5. `NavigationBar(tonalElevation = 8.dp)` has no effect with an explicit surfaceContainer color. The comment above it ("active indicator alone marks the selection") is stale since D-102.

### Expressive APIs available in 1.5.0-beta02 but unused
6. The baseline 80dp `NavigationBar` is "not recommended". The flexible bar is `ShortNavigationBar` (64dp; indicator 56×32 in secondaryContainer).
7. `MaterialExpressiveTheme`/`MotionScheme` are available. The app uses `MaterialTheme` with hand-copied standard-scheme springs (`DimaMotion`). M3 calls the expressive scheme the default for most products; the app deliberately chose standard (comment in `DimaMotion`).
8. The official `Typography.*Emphasized` styles exist (500 for display/headline/title-large/body, 700 for title-M/S and labels; baseline title-large/headline weight 400). The app sets titles and headlines to 500 and every emphasized style to 600 (D-094(8)). Korean belongs to M3's "medium" language-height group (title-large line height 31sp instead of 28sp); the app uses the Latin line heights.
9. `Shapes` now has largeIncreased/extraLargeIncreased/extraExtraLarge slots; `DimaShapes.LargeIncreased` duplicates the first.
10. Buttons do not use the expressive press shape morph (`ButtonDefaults.shapes()`). Cards use a custom scale press (`expressiveBounceClick`).
11. Loading uses a 16dp `CircularProgressIndicator` and the default pull-to-refresh indicator. M3E prescribes LoadingIndicator / ContainedLoadingIndicator for waits of 200ms–5s and for pull-to-refresh; these are still `@ExperimentalMaterial3ExpressiveApi` in 1.5.0-beta02.
12. App bars are a small 64dp `TopAppBar` with a headlineMedium SemiBold title. The small-bar spec uses titleLarge. Larger titles belong to `MediumFlexibleTopAppBar` (112dp, collapses).
13. Settings and About rows are hand-built. Expressive segmented lists (`SegmentedListItem`, 2dp gaps, 16/4dp corners) are available.

### Conflicts with standing decisions (user decision needed)
14. Last-service departures use the error roles (D-016/D-083). M3 reserves error for errors and suggests a defined static warning color with four roles.
15. Cards: every summary is an `ElevatedCard` with 20dp corners and 16dp gaps (D-081 app choice, D-079). The card spec is 12dp corners and gaps of at most 8dp, separation by tone rather than shadow ("less is more"), and no forcing content into cards.
16. Full-timetable chips look like chips but are not interactive (D-093). M3 chips are interactive elements.
17. The tertiary (warm gold) role is defined but used once. Optional: M3 gives tertiary to contrasting accents such as badges.
18. On a large screen (Tab S9) the app opens in landscape (Q-022). This is outside M3E, but the adaptive layout (rail, two-pane) is not implemented (D-054).

## Not verified
Behavior at 200% font size with the current fixed-height capsules and chips; medium/high contrast variants (a static scheme gets no system contrast levels).
